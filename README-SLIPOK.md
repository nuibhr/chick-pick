Cloudflare Worker ใช้โอนเงินและแนบสลิปสำหรับการจองใหม่ ทั้ง Open Play และโค้ช ปิด API สร้าง Stripe Checkout ใหม่แล้ว ไม่มีช่องกรอก Secret ในหน้าแอป คีย์อ่านจาก `env.SLIPOK_API_KEY` ฝั่งเซิร์ฟเวอร์เท่านั้น Node preview ไม่ได้เพิ่ม SlipOK ในรอบนี้

## ตั้งค่า

- `SLIPOK_BRANCH_ID=77946` อยู่ใน `wrangler.tidb.jsonc` เรียกเฉพาะ HTTPS `https://api.slipok.com/api/line/apikey/77946`
- ตั้ง `SLIPOK_API_KEY` เป็น Cloudflare Worker Secret โดยรัน `./scripts/configureSlipOK.ps1` จากโฟลเดอร์โปรเจกต์ สคริปต์รับค่าแบบซ่อน ไม่เก็บคีย์ลงไฟล์หรือ argument และเปลี่ยนเฉพาะ SlipOK secret ไม่แตะ TiDB, LINE หรือ Stripe secrets
- ต้องผูกบัญชีรับเงินใน SlipOK ให้ตรงกับบัญชีรับโอนในแอป ชื่อธนาคารใช้ชื่อเต็มหรือชื่อย่อที่ SlipOK รองรับ การจองเก่าเก็บบัญชีปลายทางเดิมของตัวเอง
- เจ้าของเปิดแอดมินแพลตฟอร์ม > บัญชีและการเปิดรับ เพื่อดูสถานะเชื่อมต่อและโควต้า ยังต้องทดลองตรวจสลิปของการจองจริงก่อนเรียกว่าพร้อมใช้งานจริง การมีคีย์ไม่ยืนยันแพ็กเกจหรือเงินเข้า

## การตรวจและอนุมัติ

ระบบเก็บภาพเป็นส่วนตัวและบันทึกสลิปรอตรวจก่อนเรียก SlipOK ใช้ multipart `files`, `log=true` และ `amount` จากราคาจองบนเซิร์ฟเวอร์ SlipOK จึงตรวจผู้รับที่ผูกกับสาขาและสลิปซ้ำด้วย พร้อมเก็บรายการในระบบของ SlipOK การตรวจอาจใช้โควต้าตามแพ็กเกจ

แอปตรวจซ้ำว่า API สำเร็จทั้ง response และ data, จำนวนเงินตรงถึงสตางค์, ประเทศและสกุลเงินถูกต้อง, เลขอ้างอิงใช้งานได้, ธนาคารผู้รับตรง และตัวเลขที่เปิดเผยทุกตำแหน่งของบัญชีผู้รับตรงกับบัญชีในการจองอย่างน้อยสี่หลัก เวลาโอนต้องไม่ก่อนสร้างการจองเกินห้านาทีหรือเกินเวลาปัจจุบันห้านาที ถ้ารูปแบบบัญชีปิดบังยืนยันไม่ได้ จะไม่ผ่านโดยอัตโนมัติ

เลขธุรกรรมที่ตรวจผ่านถูกกันซ้ำใน transaction ของ TiDB ข้ามก๊วนและค่าเรียน ก่อนอนุมัติด้วยคน ผล SlipOK ไม่ทำให้เงินเข้า ledger หรือค่าคอมเอง แอดมินต้องตรวจภาพและกดอนุมัติ ช่องเลขอ้างอิงและยอดของผลที่ผ่านจะแก้ไม่ได้ ฝั่งเซิร์ฟเวอร์ตรวจซ้ำก่อนลงบัญชี ผู้จัดเลือกคนเข้าสนามแยกตามเดิม

ผลผิดยอด/ผู้รับ/ซ้ำ/ภาพผิดไม่สามารถฝืนอนุมัติด้วย API ได้ แอดมินปฏิเสธพร้อมเหตุผลเพื่อให้ส่งใหม่ได้ สลิปเก่าที่ส่งก่อนเชื่อม SlipOK ยังใช้การตรวจเงินด้วยคนตามเดิม

ธนาคารล่าช้า/บริการไม่พร้อม/คีย์หรือแพ็กเกจผิด จะเก็บภาพไว้และยังไม่รับเงิน มีเวลาตรวจใหม่และปุ่มตรวจ SlipOK อีกครั้งฝั่งแอดมิน ล็อกงานตรวจ 45 วินาทีเพื่อกันคำขอพร้อมกัน และใช้ rate limit เดิม ผลดิบ upstream, คีย์, QR payload และข้อความ error ที่อาจมีคีย์ไม่ถูกส่งกลับ browser

หาก SlipOK รับคำขอแล้วแต่เครือข่ายขาดตอน การลองใหม่อาจได้รับสลิปซ้ำ `1012` ระบบจะไม่ถือว่าเป็นเงินรับ ต้องให้เจ้าของกระทบยอดก่อนตัดสินใจ ไม่อ้างว่า retry เป็น exactly-once กับบริการภายนอก

## รายการ Stripe เดิม

เก็บ signed webhook, sync, ประวัติชำระและค่าธรรมเนียมเดิมไว้เพื่อกระทบยอด ไม่สร้าง QR ใหม่และไม่เปิดให้เลือก Stripe ใน settings รายการมี QR ค้างยังล็อกการจ่ายซ้ำจน Stripe ยืนยันหมดอายุ หากเป็นรายการ `test_paid` ให้ยกเลิกการจองทดสอบแล้วจองใหม่เพื่อส่งสลิปจริง การ deploy เปลี่ยนช่องทางที่ใช้จริงเป็นโอน/แนบสลิปโดยไม่ล้างค่า settings หรือข้อมูลการจองเดิม ยังไม่ลบ Stripe secrets ก่อนเคลียร์ประวัติทั้งหมด
