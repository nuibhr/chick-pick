# แอดมินการเงินและโปรไฟล์ DUPR

## เปิดใช้งานในเครื่อง

ใช้ `pnpm dev` แล้วเปิด http://localhost:3000/?admin=1 หรือกด “แอดมิน” ที่ส่วนหัวแอป ครั้งแรกให้เจ้าของเครื่องตั้งรหัสผ่านอย่างน้อย 12 ตัวอักษร ไม่มีรหัสผ่านเริ่มต้น ระบบเก็บ salt และ scrypt hash ใน `data/admin.json` ไม่เก็บรหัสผ่านตรง ๆ เซสชันใช้ HttpOnly / SameSite=Strict cookie อายุ 8 ชั่วโมง และหมดอายุเมื่อ restart server

หน้าการเงินใหม่ใช้ `FinanceDashboard.tsx` แทนหน้า AdminDashboard เดิมที่เป็น mockup

## การเงิน

- รายรับ รายจ่าย ส่วนต่างรับ–จ่าย และยอดรอรับ/รอจ่าย คำนวณจากข้อมูลรายการ ไม่มีการเติมยอดตัวอย่างลงแดชบอร์ด
- ค่าเรียนมาจาก `data/coaching.json` โดยอ่านข้อมูลล่าสุดเมื่อโหลดรายงาน อ้างอิง enrollment ID จึงไม่คัดลอกรายรับซ้ำ
- ค่าก๊วนจำลองที่ชำระหลังอัปเดตนี้จะลงบัญชีด้วยราคาเซิร์ฟเวอร์ ไม่ใช้ราคาที่หน้าเว็บส่งมา ป้องกันรับเงินซ้ำต่อ session/player
- บันทึกรายการเองได้ แยกหมวดสนาม โค้ช ผู้จัด อุปกรณ์ การตลาด คืนเงิน และอื่น ๆ
- ยืนยันรายการ pending เป็นรับ/จ่ายแล้ว พร้อมวันที่รับ/จ่ายจริง
- ยกเลิกรายการที่บันทึกผิดโดยเก็บเหตุผลและประวัติ ไม่ลบทิ้ง การคืนเงินจริงให้สร้างรายจ่ายหมวดคืนเงินแทน
- เลือกช่วงวัน ประเภท หมวด สถานะ ค้นหา และ export CSV โดยใช้ตัวกรองเดียวกันทั้งตาราง ยอดรวม และรายงาน
- คำนวณจำนวนเงินเป็นจำนวนเต็มหน่วยสตางค์ วันที่อ้างอิง Asia/Bangkok
- เก็บบัญชี manual/game ใน `data/finance.json` เป็นการเขียนไฟล์แบบแทนที่ รองรับเซิร์ฟเวอร์ process เดียว

ส่วนต่างรับ–จ่ายเป็นยอดเงินเข้าออก ไม่ใช่กำไรตามบัญชี ไม่คำนวณ VAT ภาษี ยอดยกมา การรับรู้รายได้คอร์ส หรือรายได้ส่วนแบ่งแพลตฟอร์มอัตโนมัติ การจ่ายให้โค้ช/สนาม/ผู้จัดให้บันทึกเป็นรายจ่ายตามที่เกิดขึ้น ไม่มีการโอนเงินจริงจากปุ่มในแอป รายการอัตโนมัติแก้ไขจากต้นทาง ข้อมูลทดลองเก่าที่ไม่เคยบันทึกไม่สามารถนำเข้ารายงานย้อนหลังได้

## DUPR — สถานะปัจจุบัน

ผู้ใช้ยังไม่มีสิทธิ์ Partner API จึงยังดึงคะแนนจริงและทดสอบ live ไม่ได้ หน้าโปรไฟล์ลบคะแนนจำลองเดิมออกแล้ว แสดง `—` จนกว่าจะมีข้อมูล API จริง บันทึก DUPR ID ไว้รอเชื่อมต่อได้ ไม่ขอรหัสผ่าน DUPR และไม่ถือว่าการกรอก ID เป็นการยืนยันเจ้าของบัญชี

อ้างอิงเอกสารทางการที่ตรวจวันที่ 18 กันยายน 2026:

- [DUPR Partner OpenAPI (UAT)](https://uat.mydupr.com/api/v3/api-docs/DUPR%20Partner%20APIs)
- [Club resources](https://www.dupr.com/club-resources)
- [DUPR dashboard](https://dashboard.dupr.com/dashboard)

ตัวเชื่อมฝั่งเซิร์ฟเวอร์ใช้ `POST /auth/v1.0/token` โดยส่ง base64(ClientKey:ClientSecret) ใน x-authorization จากนั้นใช้ bearer token เรียก `GET /user/v1.0/{id}` ซึ่งต้องมี `USER::DETAIL` เก็บเฉพาะ ID ชื่อ คะแนนเดี่ยว/คู่ สถานะ reliability และเวลาดึง ไม่เก็บอีเมล ที่อยู่ หรือคำตอบดิบจาก API รองรับ NR และไม่แปลงข้อผิดพลาดให้กลายเป็นคะแนน

เมื่อได้รับสิทธิ์ ให้คัดลอก `.env.example` เป็น `.env` ตั้ง `DUPR_API_BASE_URL`, `DUPR_CLIENT_KEY`, `DUPR_CLIENT_SECRET` แล้ว restart ค่า URL ต้องเป็น HTTPS บนโดเมนทางการ DUPR และเป็น URL ที่ DUPR ออกให้ สิทธิ์ UAT กับ production อาจต่างกัน ห้ามตั้งชื่อ secret ด้วย VITE_ เพราะจะเสี่ยงเข้า browser bundle

โค้ดที่เตรียมไว้เป็นการ sync แบบ polling: หน้าโปรไฟล์ตรวจสถานะทุก 60 วินาทีเมื่อมองเห็น และเซิร์ฟเวอร์เรียก DUPR ไม่ถี่กว่า 5 นาที ปุ่มตรวจคะแนนเคารพ cache/backoff เช่นเดียวกัน เก็บ token ไม่เกิน 55 นาทีหรือก่อน expiry 1 นาที คำขอ timeout 10 วินาที จำกัดการ redirect และจัดการ 401/403/404/417/429 แสดงข้อมูลเก่าพร้อมเวลาหาก refresh ล้มเหลว คะแนน UAT แสดงป้าย Sandbox ชัดเจน ไม่ปะปนกับ production

## ขั้นตอนเปิด realtime จริง

1. ติดต่อ DUPR ขอ Partner API access สำหรับ Chick&Pick พร้อมสิทธิ์อ่านคะแนน `USER::DETAIL` และเอกสาร SSO/consent ที่ตรงกับประเภทพาร์ตเนอร์ ให้ระบุว่าต้องการแสดง Singles/Doubles และติดตามการเปลี่ยนคะแนน
2. รับ Client Key/Client Secret, production base URL, อัตราเรียก API ที่อนุญาต และวิธียืนยันลายเซ็น webhook โดยเก็บ secret ฝั่งเซิร์ฟเวอร์เท่านั้น
3. เชื่อมสมาชิก Chick&Pick กับ DUPR ผ่าน SSO ที่ DUPR อนุมัติ สำหรับ restricted partner เอกสารกำหนดให้ผู้เล่นยินยอมก่อน subscribe
4. จัด public HTTPS endpoint ที่มี certificate จริงและตรวจความถูกต้องของ webhook ตามข้อกำหนด DUPR เอกสารกำหนดให้ endpoint ตอบ 200 ต่อ registration handshake และมี webhook active ได้หนึ่ง URL ต่อ client
5. ลงทะเบียนผ่าน `POST /v1.0/webhook` แล้ว subscribe `RATING` ผ่าน `POST /user/v1.0/subscribe/webhook-event` สำหรับ ID ที่ยืนยันแล้ว เอกสารระบุว่ามี `RATING_SEED` เริ่มต้นและมี schema ให้ตรวจ
6. ตรวจ payload/signature, กัน replay และเรียง event ก่อนอัปเดตข้อมูลสมาชิก จากนั้น push ไปหน้าโปรไฟล์ด้วย SSE/WebSocket และเก็บ polling เป็น fallback

ยังไม่ได้ลงทะเบียน webhook หรือสร้าง endpoint ที่รับข้อมูลโดยไม่มีการตรวจยืนยัน เพราะยังไม่มีสิทธิ์ API, รายละเอียดการเซ็น webhook, บัญชีสมาชิกจริง และ public HTTPS deployment ดังนั้นเวอร์ชันนี้ไม่อ้างว่าเป็น realtime live

## ขอบเขตและทดสอบ

เซิร์ฟเวอร์ bind เฉพาะ `127.0.0.1` ระบบ admin/finance และ DUPR นี้ปิดใน production เช่นเดียวกับโมดูลโค้ช เพื่อไม่เปิดข้อมูล preview ที่ยังใช้ผู้เล่นร่วมกัน แม้หน้าแอดมินการเงินมีรหัสผ่าน แต่ส่วนโค้ชเดิมยังเป็น preview ที่สลับบทบาทได้ ห้ามนำ development server นี้ไปเปิดสาธารณะ ต้องเพิ่มสมาชิก สิทธิ์โค้ช การแยกเจ้าของข้อมูล ฐานข้อมูลแบบ transaction และ gateway/webhook ยืนยันเงินจริงก่อน

ทดสอบด้วย `pnpm lint`, `pnpm build`, `node --import tsx --test server/coaching.test.ts server/finance.test.ts server/dupr.test.ts` ทดสอบ DUPR ด้วย response fixture ตาม schema เท่านั้น ไม่ใช่การยืนยันว่า credential จริงทำงาน
